# 免登入唯讀分享連結

日期：2026-09-16
狀態：待審核

## 背景

沒有帳號的人目前只能看「複製 / 分享文字行程」產生的純文字，貼到 LINE 給
長輩或同行的家人。那是一份**靜態快照**：行程一改，他們手上那份就過期了，
而且沒有任何人會知道。

Tabi 的旅伴模型已經承認「有人不會有帳號」——migration 015 的
`guest:<uuid>` 就是為了長輩存在的。但那些人只出現在別人的畫面上，自己
沒有任何入口。這份 spec 補的是那個入口。

## 定位

**取代那份靜態文字，不是做一個公開的旅程網站。**

顯示範圍刻意與 `itineraryText`（`src/lib/share.ts`）完全一致：同樣的資料
進公開頁，不多一分。文字版已經在 LINE 群組裡流傳，公開頁不應該比它洩漏
更多；反過來說，比它少就沒有取代價值。

## 範圍

會做：

- `trips.share_token`，可產生、可撤銷
- 一支免登入的 RPC，回傳整份行程
- 一條 `/s/:token` 路由，唯讀、大字、無導覽
- 設定頁的產生 / 複製 / 重新產生 / 關閉

明確排除：

- 留言、按讚、任何寫入。唯讀就是唯讀。
- 公開頁的想去清單、圖片、景點連結（文字版本來就沒有這三樣）
- 自訂網址、短網址、密碼保護、有效期限
- SEO / og:image。這是給特定幾個人看的連結，不是要被搜尋到的頁面。
- 瀏覽統計

## 1. 安全模型

### 現況

`trip_preview_rpc`（009）雖然是 `security definer`，但第一行就是
`case when auth.uid() is null then null`，所以**目前沒有任何未登入的
讀取路徑**。這份設計要開的就是第一條。

### 設計

在 `trips` 加一個可為 null 的欄位：

```sql
alter table trips add column share_token uuid unique;
```

- `null` 代表沒有開啟分享，這是預設值，既有旅程全部維持關閉
- 開啟時產生一個隨機 uuid
- 「重新產生」就是換一個新的 uuid，舊連結立刻失效
- 「關閉分享」就是設回 null

用獨立 token 而不是直接用 `trips.id`，理由是**可撤銷**。邀請連結用的是
旅程 id，但那是要對方登入才能加入；唯讀連結會被轉傳到不確定的地方，必須
能在不刪掉旅程的前提下作廢。

### 誰可以開關

只有主揪。開啟分享等於把整份行程交出去，這個決定不該讓任何成員都能做，
也不該讓任何成員能把別人開的連結作廢。

沿用 008 的 `get_trip_owner_email()` 判斷，不新增判斷方式。

### 欄位授權

008 把 `trips` 的 UPDATE 收成逐欄授權，所以 `share_token` **不會**加進
`grant update`。它只能透過下面的 RPC 改，客戶端無法直接寫。

## 2. 公開讀取 RPC

```sql
public_trip_rpc(p_token uuid) returns jsonb
```

`security definer`，不檢查 `auth.uid()`，這是它存在的理由。

`p_token is null` 時直接回 null，否則找不到 token 的旅程會被
`where share_token = p_token` 配到任何 `share_token is null` 的列。
這是這支函式最容易寫錯的地方。

### 回傳形狀

```jsonc
{
  "name": "沖繩四日遊",
  "start_date": "2026-11-02",
  "end_date": "2026-11-05",
  "notes": "BR116 07:35 桃園→那霸",
  "days": [
    {
      "date": "2026-11-02",
      "label": "飛行日",
      "events": [
        {
          "type": "shared",
          "title": "早餐",
          "time_start": "08:30",
          "time_end": "09:30",
          "location": "國際通",
          "notes": "",
          "groups": []
        },
        {
          "type": "fork",
          "time_start": "13:00",
          "time_end": "17:00",
          "groups": [
            { "label": "爸爸、媽媽", "title": "潛水", "location": "真榮田岬" },
            { "label": "其他人", "title": "逛街", "location": "國際通" }
          ]
        }
      ]
    }
  ]
}
```

### email 不出去

`fork_items` 裡是 email 和 `guest:<uuid>`。公開端點**不回傳 emails
陣列**，而是在伺服器端就把分組解析成 `label` 字串——等同於
`groupLabel()` 在前端做的事。

文字版分享出去的本來就只有名字，公開頁沒有理由比它多洩漏一組 email。
同理不回傳 `avatar_url`（Google 頭像網址）與成員清單本身。

這代表 `groupLabel` 的邏輯會有兩份實作（一份 TS、一份 SQL）。這是刻意
付出的代價：少一個洩漏面，換一份需要同步的邏輯。兩邊的規則寫在
`src/lib/fork.ts` 的註解與 migration 註解中互相指向。

### 不回傳的欄位

`id`、`trip_id`、`day_id`、`sort_order`、`image_url`、`link_urls`、
`fork_items` 原始值、`owner_email`、成員清單。

前三個是內部識別碼，公開頁不需要；後面幾個是刻意對齊文字版的範圍。

## 3. 路由與畫面

`/s/:token`，在 `App.tsx` 的**未登入分支也要註冊**，否則沒有帳號的人會
被導去登入頁——那正是這個功能要解決的問題。

```
未登入：/join/:tripId、/s/:token、其他 → LoginPage
已登入：既有路由 + /s/:token
```

### 畫面

單欄、由上而下、沒有底部導覽、沒有齒輪、沒有任何可以點進去的東西。

- 旅程名稱與日期範圍
- 重要資訊（有才顯示）
- 一天一段：日期 + 當天主題，接該天的行程
- 每筆行程：時間、名稱、地點；分頭行動顯示各組的 `組名：活動（地點）`
- 地點沿用 `mapsUrl()` 開 Google Maps。這是長輩最可能真的會點的東西。

字級比主畫面大一級（主畫面多在 11–15px，這裡以 15–17px 為基準），因為
預設讀者就是長輩。

### 三種狀態

| 狀態 | 畫面 |
|---|---|
| 載入中 | 「載入行程中...」 |
| token 無效或已撤銷 | 「這個連結已失效,請跟旅程的主揪要新的連結。」 |
| 正常 | 行程 |

失效不解釋原因（撤銷？打錯？旅程已刪？），對拿到舊連結的人來說沒有差別。

## 4. 設定頁

放在既有「分享行程」區塊內，與純文字分享並列——它們是同一件事的兩種做法。

未開啟時：

```
[ 建立唯讀連結 ]
沒有帳號的人也能看,而且會跟著更新。
```

已開啟時：

```
https://tabi-2g7.pages.dev/s/<token>     [複製]
[ 重新產生 ]  [ 關閉分享 ]
重新產生後,舊的連結立刻失效。
```

非主揪看到的是唯讀狀態：有連結就能複製，但沒有產生 / 重新產生 / 關閉。
`subscribeToTripData` 對 `trips` 是 `select('*')`，008 只收了 UPDATE 的
逐欄授權、沒有動 SELECT，所以 `share_token` 本來就會隨旅程資料送到每個
成員手上，不需要額外的讀取路徑。

「重新產生」與「關閉分享」都要 `ConfirmSheet`，因為兩者都會讓已經發出去
的連結立刻失效，而且無法復原。

## 5. 測試

純函式與 SQL 分開驗。

**SQL**（在 `begin; ... rollback;` 裡對正式資料庫實跑，用
`set local request.jwt.claims` 模擬不同身分；送出前先故意改錯一個期望值，
確認探針真的會失敗，否則全過與根本沒跑到長得一樣）：

- 主揪可以產生 token；非主揪不行
- 重新產生後，舊 token 查不到東西
- 關閉後，token 查不到東西
- `public_trip_rpc(null)` 回 null，不會配到任何 `share_token is null` 的旅程
- 未登入（`role = anon`）確實讀得到已開啟的旅程
- 回傳的 jsonb 裡不含任何 `@`，也不含 `guest:`
- 分組標籤與 `groupLabel()` 對同一筆資料的輸出一致

**前端**：

- `/s/:token` 在未登入狀態下不會被導去登入頁
- 三種狀態各渲染一次
- 分頭行動顯示組名與活動
- 設定頁：非主揪看不到產生 / 重新產生 / 關閉

---

## 6. 風險

**拿到網址的人就看得到整份行程，包含重要資訊裡的訂房與航班代號。**

這是這個功能的本質，不是可以設計掉的東西。緩解方式是：

1. 預設關閉，要主揪主動開
2. 可撤銷，且撤銷是一個動作
3. 設定頁的說明文字直接寫明「拿到連結的人都看得到,包含重要資訊」

風險等級與現況相當：純文字行程本來就已經包含重要資訊，而且一旦貼進 LINE
群組就再也收不回來。唯讀連結至少還能撤銷。

---

## 7. 實作順序

1. Migration：`share_token` 欄位 + 三支 RPC（產生 / 撤銷 / 公開讀取）
2. `db.ts` 的三個對應函式 + 測試
3. `/s/:token` 路由與唯讀頁 + 測試
4. 設定頁區塊 + 測試

每一步可獨立驗證；第 1 步套用到線上之後，第 2–4 步未上線前不會有任何
效果，因為沒有任何 token 被產生過。
